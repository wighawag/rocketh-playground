# `$lib/playground`: compile, transpile and run, in four workers

The playground's core: what turns the project's files into a run of its deploy scripts. Plain `.ts`, no Svelte, no `$app/*`; each worker entry is a thin file over a module the node tests drive directly (`test/lib/playground/`).

| Thread | Entry | Logic | In | Out |
| --- | --- | --- | --- | --- |
| TypeScript worker (module) | `typescript/typescript.worker.ts` | `typescript/typescript-host.ts`, `typescript/transpile.ts`, `typescript/language-service.ts` | project files, artifact types | CommonJS per file, run-time imports, syntax diagnostics; the editor's diagnostics, completion and hover |
| compiler worker (CLASSIC) | `compiler/compiler.worker.ts` | `compiler/compiler-host.ts`, `compiler/solidity.ts` | the soljson URL, then project files | load progress, solc diagnostics, `generated/artifacts/*.js` and their `.d.ts` |
| EVM worker (module) | `evm/evm.worker.ts` | `evm/evm-host.ts` | node options, an IndexedDB name | webevm's node proxy; `serveOn(port)` |
| runner worker (module) | `runner/runner.worker.ts` | `runner/runner-host.ts`, `runner/run.ts` | a port the EVM worker serves; transpiled modules | log entries, deployment store changes, the outcome |

- **The editor is `editor/code-editor.ts`**, CodeMirror 6 on the page's thread (`components/playground/CodeEditor.svelte` mounts it): TypeScript syntax for `.ts`, `@replit/codemirror-lang-solidity` for `.sol`, records read-only. It is presentation only. Every edit goes to the session, which holds the text, so switching files keeps what was typed; the view is rebuilt when the file, the language service or the artifact types change (that loses the undo history at those moments).
- **The language service lives in the TypeScript worker**, beside the transpiler, through `@valtown/codemirror-ts` and `@typescript/vfs` (`typescript/language-service.ts`). The syntax-only editor is usable first; the session starts the language service once the rest has booted, and the editor attaches it when it is ready. It types the project with `hardhat-deploy init`'s compiler options plus the `webworker` lib (`typescript/project-options.ts`: `console` resolves, `document` does not, as in the runner). A type error never blocks Deploy: a run is transpiled, not type-checked.
- **Its declarations are a build asset**, not part of the worker: `scripts/declarations.mjs` records what TypeScript reads to type a file importing every package in `runner/bare-modules.ts` (and the type-only `rocketh/types`), lays it out npm-style (a second version of a package, such as viem's abitype, nested under its dependent), and `vite.playground.ts` writes it to `typescript/generated/declarations.json` (git-ignored), which the worker imports `?url` and fetches when the language service starts.
- **Artifact types before Deploy.** `compiler/solidity.ts` writes a `.d.ts` beside each generated `.js`, as hardhat-deploy's "javascript" generator does (`export declare const Artifact_<Name>: <the artifact as a literal type>;`); that is what types `artifacts.Counter` and makes a wrong constructor argument an error. The session compiles in the background as soon as the compiler is ready, and again after an edit to a `.sol` file (debounced), keeping the last types while a contract does not compile.
- **The page's side is `session.ts`**: a Svelte store holding the files, the transcript, the records and the chain's height, with `start`, `deploy`, `stop`, `edit` and `select`. The workers are a parameter (`workers.ts` makes the browser's), so `test/lib/playground/session.test.ts` runs a whole session with each host on a MessageChannel (`language-service.test.ts` drives the language service alone); `e2e/tests/playground.e2e.ts` runs it in Chromium against the build.
- **User code runs only in the runner.** It resolves imports through `runner/registry.ts`: relative paths to project files, the packages in `runner/bare-modules.ts` (each a lazy chunk, loaded before a run that imports it), and nothing else, with an error naming the import and the list.
- **The config is the reader's**, with the accounts replaced by the throwaway keys in `runner/test-keys.ts`, the in-tab chain declared and the environment named `playground` (`runner/compose-config.ts`).
- **rocketh's transcript** needs a `named-logs` factory installed before any rocketh module is evaluated: `runner/log-hook.ts`, the runner's first import.
- **The starting project** is `web/project-template/`, the published hardhat-deploy template, unedited (`project/template.ts`, refreshed by `scripts/update-project-template.mjs`). **The compiler** is the soljson pinned in `web/solc.json`, copied into `static/solc/` by `scripts/soljson.mjs`.

Design: `work/specs/proposed/rocketh-playground.md` in the rocketh repository, and the runner spike, `docs/spikes/runner/` on branch `spike/runner`.
